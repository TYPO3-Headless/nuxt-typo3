title: Access to API data
---

## Accessing Initial Data 

`nuxt-typo3` exposes **initial data** directly through the composable:

```ts
const { initialData } = useT3Api()
```

The initial data is fetched once on the initial server-side render at the plugin level.
Because it’s retrieved in the SSR context, it becomes globally available across your entire application — in app.vue, layouts, and pages.

This approach ensures that all parts of your app share the same data source and eliminates the need to manually re-fetch or pass props down the component tree.

initialData is ready to use anywhere in your Nuxt app right after the first load.

## Fetching Initial Data 

You can also manually re-fetch initial data at any time by calling:

```ts
const { getInitialData } = useT3Api()
const newInitialData = await getInitialData()
```

This is useful if you need to refresh global data after certain user actions, or dynamically fetch data for a specific site context.

## Accessing Page Data

`nuxt-typo3` exposes **page data** directly through the composable:

```ts
const { pageData } = useT3Api()
```

Unlike initial data, page data is dynamic and tied to the current route.

It is fetched:
+ Once on the initial SSR render (on the server, in the plugin)
+ On the client, each time the route changes (at the page component level)

This guarantees that the page content always reflects the current route — server-rendered for the first request, and client-updated during navigation.

## Fetching Page Data
You can also manually re-fetch page data at any time by calling:

```ts
const { getPage } = useT3Api()
const newPageData = await getPage('/about-us')
```

This allows you to programmatically fetch specific TYPO3 pages without triggering navigation — for example, when preloading or refreshing a section of your app.


::note
Alternatively, instead of using composables like `useT3Api()` or `useT3Page()` to watch for data changes, you can use [module hooks](/guide/hooks) to react to updates in initialData and pageData globally.
::
