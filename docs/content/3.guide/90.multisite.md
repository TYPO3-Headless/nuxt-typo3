title: Multi-Site Configuration
---
`nuxt-typo3` supports multiple sites (domains) with different configurations per domain. This is perfect for:

- 🌍 Multi-domain applications (e.g., `example.com`, `example.de`, `example.pl`)
- 🏢 Multi-tenant SaaS applications
- 🌐 Regional websites with different TYPO3 backends

## Basic Multi-Site Setup

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  typo3: {
    sites: [
      {
        hostname: 'example.com',
        api: {
          baseUrl: 'https://api-us.example.com'
        },
        i18n: {
          default: 'en',
          locales: ['en']
        }
      },
      {
        hostname: 'example.de',
        api: {
          baseUrl: 'https://api-eu.example.com'
        },
        i18n: {
          default: 'de',
          locales: ['de', 'en']
        }
      }
    ]
  }
})
```

### Multiple Hostnames Per Site

One site can handle multiple hostnames (useful for dev/staging/production):
```ts [nuxt.config.ts]
export default defineNuxtConfig({
  typo3: {
    sites: [
      {
        hostname: ['example.com', 'www.example.com', 'localhost:3000'],
        api: {
          baseUrl: 'https://api.example.com'
        },
        i18n: {
          default: 'en',
          locales: ['en']
        }
      },
      {
        hostname: ['shop.example.com', 'shop.localhost:3000'],
        api: {
          baseUrl: 'https://api-shop.example.com'
        },
        i18n: {
          default: 'en',
          locales: ['en']
        }
      }
    ]
  }
})
```

## How Domain Detection Works

The module automatically detects the current domain and loads the appropriate configuration:
```
1. User visits → https://example.de/products
2. Module extracts hostname → 'example.de'
3. Finds matching site in config → sites[1]
4. Loads site-specific config
5. All API calls use the correct backend
```


::warning
**Environment Variables Limitation:** Native Nuxt environment variable syntax (e.g., `NUXT_PUBLIC_TYPO3_SITES_0_API_BASE_URL`) does **not work** for nested arrays in `sites` configuration due to how Nuxt handles runtime config merging.
