`nuxt-typo3` can automatically escape slashes in API response data to prevent SEO issues caused by crawlers misinterpreting data fields as valid URLs.

## The Problem

Search engine bots and crawlers scan your JSON API responses looking for URLs. When they find strings containing slashes like:
```json
{
  "slug": "/products/featured",
  "breadcrumbs": [
    { "title": "Home", "link": "/home" },
    { "title": "Products", "link": "/products/all" }
  ]
}
```

Bots assume these are valid page URLs and attempt to visit them. If these strings are just data fields (not actual pages), it results in:
- ❌ 404 errors in your logs
- 🤖 Crawl budget waste
- 📉 Negative SEO impact
- 🚨 False alarms in monitoring tools

## Solution: Escape Slashes

By escaping slashes (`/` → `\/`) in your API responses, crawlers ignore these strings while your application still works correctly.

## Basic Setup
```ts [nuxt.config.ts]
export default defineNuxtConfig({
  typo3: {
    features: {
      backslashApiProperties: ['slug', 'breadcrumbs.*.link']
    }
  }
})
```

This configuration will:
- ✅ Escape slashes on the **server** (SSR & API responses)
- ✅ Keep backslashes on the **client** by default (safe mode)
- ✅ Prevent crawler 404 errors

## How It Works

**Default Behavior (Safe Mode):**
```
1. Server fetches from TYPO3 API:
   { "slug": "/products/featured" }

2. Plugin escapes slashes:
   { "slug": "\\/products\\/featured" }

3. Server sends to browser (crawlers see escaped version)

4. Client keeps escaped data:
   { "slug": "\\/products\\/featured" }

5. Your components work with escaped data
```

**With Client Unescaping Enabled:**
```
1. Server fetches from TYPO3 API:
   { "slug": "/products/featured" }

2. Plugin escapes slashes:
   { "slug": "\\/products\\/featured" }

3. Server sends to browser (crawlers see escaped version)

4. Client unescapes after hydration:
   { "slug": "/products/featured" }

5. Your components work with normal data
```

## Property Path Syntax

### Simple Properties
```ts
backslashApiProperties: ['slug', 'title']
```

### Nested Objects
```ts
backslashApiProperties: ['meta.canonicalPath', 'seo.ogUrl']
```

### Arrays with Wildcards
```ts
backslashApiProperties: [
  'breadcrumbs.*.link',      // All links in breadcrumbs array
  'navigation.*.slug'         // All slugs in navigation array
]
```

### Multi-Level Arrays
```ts
backslashApiProperties: [
  'menu.items.*.children.*.link',  // Nested navigation
  'products.*.variants.*.url'      // Product variants
]
```

## Advanced Configuration

### Separate Properties per Data Type
```ts [nuxt.config.ts]
export default defineNuxtConfig({
  typo3: {
    features: {
      backslashApiProperties: {
        pageDataProps: [
          'slug',
          'breadcrumbs.*.link',
          'navigation.*.url'
        ],
        initialDataProps: [
          'menu.items.*.link',
          'footer.links.*.path'
        ],
        unbackslashOnClient: false // default
      }
    }
  }
})
```

### Enable Client Unescaping (Advanced)

If you need normal slashes on the client and are sure it won't cause hydration issues:
```ts [nuxt.config.ts]
export default defineNuxtConfig({
  typo3: {
    features: {
      backslashApiProperties: {
        pageDataProps: ['slug'],
        initialDataProps: ['menu.items.*.link'],
        unbackslashOnClient: true // Enable client-side unescaping
      }
    }
  }
})
```

::warning
**Hydration Mismatch Warning:** Setting `unbackslashOnClient: true` may cause hydration mismatches if the affected properties are rendered in your SSR HTML output. 

Only enable client-side unescaping if these properties are:
- Used exclusively in client-side navigation logic
- Not rendered directly in templates during SSR
- Handled in `onMounted()` or client-only components

The default `false` value is safer and recommended for most use cases.
::

## Multi-Site Configuration

Each site can have different properties to escape:
```ts [nuxt.config.ts]
export default defineNuxtConfig({
  typo3: {
    sites: [
      {
        hostname: 'example.com',
        features: {
          backslashApiProperties: ['slug', 'breadcrumbs.*.link']
        }
      },
      {
        hostname: 'shop.example.com',
        features: {
          backslashApiProperties: {
            pageDataProps: ['slug', 'products.*.url'],
            unbackslashOnClient: true // Only if needed
          }
        }
      }
    ]
  }
})
```


## Troubleshooting

### Escaped Slashes Visible in UI

**Problem:** You see `\/` instead of `/` in your rendered content

**Solution:** This is the default safe behavior. If you need normal slashes:
1. Set `unbackslashOnClient: true` to unescape after hydration
2. Or manually handle unescaping in your components where needed:
```ts
const displaySlug = slug.replaceAll('\\/', '/')
```

### Hydration Mismatch Error

**Problem:** Vue warns about hydration mismatch after setting `unbackslashOnClient: true`

**Solution:** The escaped property is being rendered in SSR. Either:
1. Keep `unbackslashOnClient: false` (default, recommended)
2. Use the property only in client-side logic (`onMounted`, `<ClientOnly>`)
3. Remove the property from SSR templates

### Bots Still Crawling Escaped URLs

**Problem:** Crawlers are still finding and visiting the URLs despite escaping

**Solution:** 
1. Verify escaping is working: check the HTML source (`view-source:`)
2. The property might not be in the configured list
3. Check if other API endpoints are exposing unescaped data

### Property Not Being Escaped

**Problem:** A property you configured isn't being escaped

**Solution:**
1. Check the path syntax (use `.*` for arrays)
2. Verify the property exists in the API response
3. Check if you're using `pageDataProps` vs `initialDataProps` correctly
4. Ensure the feature is enabled in the correct site configuration (for multi-site)

## Configuration Reference

### `backslashApiProperties`
- **Type:** `Array<string> | Object`
- **Default:** `undefined`

### `pageDataProps`
- **Type:** `Array<string>`
- **Default:** `[]`
- **Description:** Properties to escape in `pageData` (route-specific data)

### `initialDataProps`
- **Type:** `Array<string>`
- **Default:** `[]`
- **Description:** Properties to escape in `initialData` (global data like menus)

### `unbackslashOnClient`
- **Type:** `boolean`
- **Default:** `false`
- **Description:** Remove backslashes on client after hydration
- **Warning:** May cause hydration mismatches. Only enable if properties are not SSR-rendered.

## Best Practices

1. **Start Conservative:** Begin with just `['slug']` and add more as needed
2. **Use Wildcards:** Leverage `.*` for arrays instead of hardcoding indices
3. **Keep Default Behavior:** Leave `unbackslashOnClient: false` unless you have a specific need
4. **Test in Production:** Verify with `view-source:` that escaping works
5. **Monitor 404s:** Track if bot-related 404 errors decrease after implementation
6. **Handle Display:** If showing escaped values to users, manually unescape in components where needed
