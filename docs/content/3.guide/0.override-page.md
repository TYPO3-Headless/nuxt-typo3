The Nuxt-TYPO3 library provides a flexible architecture that allows you to customize and override the default views. One such case is the "catch-all route" page view, which is defined in Nuxt3 by the `[...slug].vue` file. If you wish to override this view, this guide will show you how to accomplish it.

## What is a Catch-all Route Page View?

A catch-all route page view is essentially a wildcard route that matches all paths where a specific page is not defined. In Nuxt-TYPO3, it is utilized to handle page requests dynamically, serving the content fetched from the TYPO3 API.


::tip
You can read more [here](https://nuxt.com/docs/guide/directory-structure/pages#catch-all-route)
::


## How to Override a Catch-all Route Page View?

Overriding a catch-all route page view involves creating a new `[...slug].vue` file in the `pages` directory of your application.

Here is how the `[...slug].vue` page is implemented in Nuxt-TYPO3:

```vue
<template>
  <T3BackendLayout
    v-if="pageData?.content"
    :name="backendLayout"
    :content="pageData.content"
  />
</template>

<script setup lang="ts">
const { headData, pageData, backendLayout, frontendLayout, getPageData } = await useT3Page()
useHead(headData);
watch(() => useRoute().query, getPageData)
</script>
```

In this example, the `<T3BackendLayout>` component is used to render the page content based on provided Backend Layout name.

To override this behavior, follow the steps below:

### Step 1: Create a new `[...slug].vue` file

Create a new `[...slug].vue` file in your application's `pages` directory. This file should define a Vue component for your custom page view.

### Step 2: Customize the template and script

Update the template and script to suit your needs. Your custom component will have access to the `pageData` object, which contains the page content fetched from the TYPO3 API.

```vue
<template>
  <NuxtLayout :name="frontendLayout">
    <!-- Your custom presentation here -->
    <T3BackendLayout
      v-if="pageData?.content"
      :name="backendLayout"
      :content="pageData.content"
    />
    <!-- Your custom presentation here -->
  </NuxtLayout>
</template>

<script setup lang="ts">
const { headData, pageData, backendLayout, frontendLayout, getPageData } = await useT3Page()
useHead(headData);
definePageMeta({
  t3Page: true,
  layout: false
})
watch(() => useRoute().query, getPageData)
// Your custom logic here
</script>
```

::warning
The `t3Page: true` route meta flag is **required** on your custom `[...slug].vue`. Nuxt-TYPO3 only resolves page data (including the server-side prefetch) for routes that declare `meta.t3Page`. The module's default catch-all sets this flag for you; when you override the page with your own file, you must set it via `definePageMeta` — otherwise the server-side page fetch is skipped and `pageData` stays empty on first load.
::

With these steps, your custom page view will be used for all routes matching the `[...slug]` pattern.

## Page meta flags

Nuxt-TYPO3 decides what to do for a given route based on two **route meta** flags. Because Nuxt declares `RouteMeta extends PageMeta`, you can set them with `definePageMeta(...)` and read them back from `route.meta` — both are fully typed by the module.

| Flag | Type | Default | Effect |
| --- | --- | --- | --- |
| `t3Page` | `boolean` | _unset_ | When `true`, the module resolves TYPO3 page data for the route (server-side prefetch + `useT3Page`). When unset, the route is left completely untouched. |
| `t3InitialData` | `boolean` | _unset_ (enabled) | Set to `false` to skip the [initial data](/guide/access-to-api-data) fetch for this route while still resolving page data. Has no effect unless the `initialDataPlugin` feature is enabled. |

The module's default catch-all route is registered with `t3Page: true` (and leaves `t3InitialData` unset, so initial data is fetched). You only touch these flags when you define your own pages.

### `t3Page` — opt a route into TYPO3 handling

Set it on any page that should be rendered from TYPO3 page data, e.g. a custom catch-all or a route that mixes TYPO3 content with your own logic:

```vue
<script setup lang="ts">
definePageMeta({ t3Page: true })

const { pageData, headData } = await useT3Page()
useHead(headData)
</script>
```

### `t3InitialData` — skip the initial data fetch

On a TYPO3-handled route you can opt out of the initial data request (for example a landing page that does not need the global navigation payload) while still rendering page content:

```vue
<script setup lang="ts">
definePageMeta({
  t3Page: true,
  t3InitialData: false // page data is still fetched, initial data is not
})

const { pageData } = await useT3Page()
</script>
```

::tip
The flag is checked with strict equality (`=== false`), so only an explicit `false` disables the fetch. Leaving it unset keeps initial data enabled.
::

## Static and custom pages

Because TYPO3 handling is gated on the `t3Page` flag, any page **without** it is left completely untouched by the module. This means you can freely add your own static pages (e.g. `pages/contact.vue`) or your own dynamic pages (e.g. `pages/products/[slug].vue`) alongside the TYPO3 catch-all — the module will not attempt to fetch TYPO3 data for them, so they render normally instead of triggering a "page not found" error from the API.

```vue [pages/contact.vue]
<template>
  <!-- a plain Nuxt page, never handled by TYPO3 -->
  <h1>Contact us</h1>
</template>
```

::warning
If you re-implement the catch-all with your own `[...slug].vue`, that file is treated like any other page: it will **not** receive TYPO3 page data unless you add `definePageMeta({ t3Page: true })`. Overriding only the visual presentation (via layouts or component overrides) keeps the module's flag intact and does not require this.
::
