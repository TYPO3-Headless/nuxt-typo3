Configure nuxt-typo3 with the `typo3` property or use runtime config for environment-specific settings.

## Basic Configuration

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  typo3: {
    api: {
      baseUrl: 'https://api.t3pwa.com'
    },
    i18n: {
      default: 'en',
      locales: ['en', 'de', 'pl']
    }
  }
})
```

## Runtime Configuration

Runtime config allows you to override settings at runtime and separate public (client-side) from private (server-side) configuration.

#### Public Runtime Config

Public configuration is exposed to both server and client:
```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      typo3: {
        api: {
          baseUrl: 'https://api.t3pwa.com'
        },
        i18n: {
          default: 'en',
          locales: ['en', 'de', 'pl']
        }
      }
    }
  }
})
```

#### Private Runtime Config (Server-only)

Private configuration is **only available on the server-side** and never exposed to the client. This is perfect for use faster internal routing in containerized environments

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    // ✅ Server-only config (never exposed to client)
    typo3: {
      api: {
        baseUrl: 'http://typo3-api.internal:8080',  // Internal Kubernetes/Docker URL
      }
    },
    
    // ✅ Public config (exposed to client)
    public: {
      typo3: {
        api: {
          baseUrl: 'https://api.t3pwa.com'  // Public URL for client
        },
        i18n: {
          default: 'en',
          locales: ['en', 'de']
        }
      }
    }
  }
})
```

### Config Merging Strategy

**Private config overrides public config on the server-side**, allowing you to use different settings for SSR vs client-side rendering:
```ts
// Server-side (SSR):
// - Uses runtimeConfig.typo3 (private)
// - Merged with runtimeConfig.public.typo3
// - Private settings take precedence
// Result: baseUrl = 'http://typo3-api.internal:8080' ✅ Fast internal network!

// Client-side:
// - Uses only runtimeConfig.public.typo3
// - No access to private config
// Result: baseUrl = 'https://api.t3pwa.com' ✅ Secure public URL!
```

### Environment Variables

You can override runtime config with environment variables:
```bash [.env]
# Private (server-only)
NUXT_TYPO3_API_BASE_URL=http://typo3-api.internal:8080

# Public (exposed to client)
NUXT_PUBLIC_TYPO3_API_BASE_URL=https://api.t3pwa.com
```

## `baseUrl`

This field provides the base site URL for setting the default URL for handling canonical and hreflang links. It is an optional field, but if left empty, canonical and hreflang links will not be set automatically.

```ts
export default defineNuxtConfig({
  typo3: {
    baseUrl: 'https://mywebsite.com'
  }
})
```

## `api`

This provides API information.

```ts
export default defineNuxtConfig({
  typo3: {
    api: {
      baseUrl: 'https://api.t3pwa.com',
      headers: {},
      credentials: 'omit',
      proxyHeaders: false,
      allowQuery: true,
      endpoints: {
        initialData: '?type=834',
        initialDataFallback: '/?type=834'
      }
    },
  }
})
```

### `baseUrl`
- Required
- Default: `'https://api.t3pwa.com'`

Define your TYPO3 API host.

### `headers`
- Optional
- Default: `{}`

Define default headers for the HTTP client.

### `credentials`
- Optional
- Default: `'omit'`
- Available values: `'include' | 'omit' | 'same-origin'`

Configure credentials for the HTTP client.

### `proxyHeaders`
- Optional
- Default: `'false'`
- Available values: `Boolean | Array<string>`

Should the API Client proxy headers from TYPO3 to a Node.js Response? You can provide an array of strings with header names.
All headers should be provided as lower-case.
[Read more about headers](/guide/headers)

### `proxyReqHeaders`
- Optional
- Default: `'false'`
- Available values: `Boolean | Array<string>`

Should the API Client proxy headers from Node.js Requets to TYPO3 API? You can provide an array of strings with header names.
All headers should be provided as lower-case.
[Read more about headers](/guide/headers)

### `allowQuery`
- Optional
- Default: `'true'`
- Available values: `Boolean | Array<string>`

Should the API provide query parameters for page calls? 
You can provide an array of strings with header names.
### `endpoints` 

This provides custom endpoint settings.

#### `initialData?`
- Optional
- Default: `/?type=834`

Define the endpoint to fetch TYPO3 initialData. 

::warning
Be aware that an endpoint starting with a slash means the module fetches `InitialData` only for the main page on initial load (including the current locale). When you omit the slash, `InitialData` will be fetched for the current page.
::

#### `initialDataFallback?`
- Optional
- Default: `/?type=834`
- Available values: `Boolean | String`

Define fallback for initialData.

## `i18n`
This provides available locales.

```ts
export default defineNuxtConfig({
  typo3: {
    i18n: {
      default: 'en',
      locales: ['en']
    }
  }
})
```

### `default`
- Optional
- Default: `'en'`

Default locale.


### `locales` 
- Optional
- Default: `[en]`

Array of available language codes. They are used to detect the language in the current URL.


## `features?`

Switch off/on default features.

```ts
export default defineNuxtConfig({
  typo3: {
    features: {
      i18nMiddleware: true,
      initialDataPlugin: true,
      dynamicPageKey: true
    }
  }
})
```


### i18nMiddleware
- Optional
- Default `true`
  
Enable/Disable middleware responsible for language detection.

### initialDataPlugin
- Optional
- Default `true`
  
Enable plugin responsible for fetching initial data on first request 


### dynamicPageKey
- Optional
- Default `false`
  
Generate dynamic page key in async data.

* When true: `t3:page:7CGLncT6qkCiXCfgr82fSJuedTJ20uMqdxaGNkVr9Fc` (route.fullPath hashed)
* When false: `t3:page`

### backslashApiProperties
- Optional
- Default `undefined`

Escape slashes in API data properties to prevent crawlers from treating data fields as valid URLs.

**Simple usage:**
```ts
backslashApiProperties: ['slug', 'breadcrumbs.*.title']
```

**Advanced configuration:**
```ts
backslashApiProperties: {
  pageDataProps: ['slug', 'navigation.*.link'],
  initialDataProps: ['menu.items.*.path'],
  unbackslashOnClient: false // default: true
}
```

#### pageDataProps
- Optional
- Type: `Array<string>`

Properties to escape in `pageData`. Supports nested paths and wildcards (`navigation.*.link`).

#### initialDataProps
- Optional
- Type: `Array<string>`

Properties to escape in `initialData`. Supports nested paths and wildcards (`menu.items.*.slug`).

#### unbackslashOnClient
- Optional
- Default `false`

Remove backslashes on client-side after hydration.

::warning
May cause hydration mismatches if properties are SSR-rendered. Set to `false` for safer behavior.
::
